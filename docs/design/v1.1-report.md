## 1. What changed, screen by screen

Every screen now takes its colours, type, spacing and radii from the theme.
A guard test (`test/assets/design_system_test.dart`) fails if a screen
reintroduces a raw colour, a Material palette colour, a literal font size,
light/dark branching or ScreenUtil units.

## 4. Firestore rules you need to deploy

Only `firestore.rules` changed; deploying is yours (`firebase deploy --only
firestore:rules`). Nothing was deployed from here and no console setting or
live data was touched. All changes are **additive**: no existing field
became required, no existing rule was loosened.

1. **`users/{uid}`** — new optional field `sex` (`'female'` or `'male'`,
   or null). Added to `hasOnly`.
2. **`users/{uid}/medical_dates/{id}`** — four new optional fields:
   `givenDate` (timestamp), `clinic` (≤ 120 chars), `lot` (≤ 60), `note`
   (≤ 500). Added to `hasOnly`. Deliberately *not* required to sit on a
   Completed dose, so a v1.0 build still installed somewhere can undo with
   `{state}` only.
3. **`users/{uid}/measurements/{id}`** *(new)* — owner-only; `hasOnly(date,
   weightKg, heightCm, headCm, note)`; `date` timestamp; at least one value;
   weight 0.3–150 kg, height 20–220 cm, head 20–70 cm; note ≤ 500.
4. **`users/{uid}/reminders/{id}`** *(new)* — owner-only; `hasOnly(title,
   note, dateTime, repeat, enabled)`; title 1–100 chars; note ≤ 500;
   `dateTime` timestamp; `repeat` in none/daily/weekly/monthly; `enabled`
   bool.
5. Three helper functions (`isOptionalTimestamp`, `isOptionalNumberIn`,
   `isOptionalOneOf`).

The default-deny catch-all is unchanged.

**Existing users stay valid** — tested on the emulator:
- a v1.0 profile without `sex` still creates/updates;
- a v1.0 dose without record fields still updates its state;
- account deletion now also deletes `measurements` and `reminders` (the
  rules allow the owner to delete both);
- `users/{uid}/secrets/…` and any other undeclared path stays denied.

**Order matters:** deploy the rules **before** (or together with) shipping
the v1.1 build. A v1.1 app against the old rules would get permission
errors when saving a dose record, a measurement, a reminder or the sex.

## 5. Decisions for you

1. **WHO data licence (CC BY-NC-SA 3.0 IGO, non-commercial).** Fine for a
   free app with no ads or purchases. If Baby Vax is ever monetised, WHO's
   permission is needed or the percentiles must go. Attribution is on the
   Growth screen and in `THIRD_PARTY.md`.
2. **Play "Data safety" form and privacy policy.** v1.1 stores more health
   information in Firestore: the baby's sex, dated measurements, where and
   when doses were given (clinic, lot, notes) and the parent's reminders.
   The listing and `docs/privacy-policy.html` should say so before release.
   I did not edit the policy (it is a legal text).
3. **Sex is required at sign-up** (girl / boy) because the WHO standards
   are sex-specific. If you would rather allow "prefer not to say", the
   growth screen already handles a missing sex (no percentiles).
4. **Birth-date correction moves the schedule.** Profile edit now allows
   it, after a confirmation; generated doses move, states are kept, custom
   dates stay. Say if you would rather keep the birth date locked.
5. **Email is read-only in the profile.** Changing the sign-in email
   properly needs Firebase's verify-before-update flow; not built.
6. **Version number** — `pubspec.yaml` is still `1.0.0+1`; not bumped,
   since the release number is yours to choose (CI sets the build number
   on signed builds).
7. **iOS icons** were regenerated with the new branding (by
   `flutter_launcher_icons`), although only Android ships today.
8. **Desktop plugin registrants** (linux/windows/macos) were not
   committed, as instructed. `printing` is a new plugin, so a desktop build
   would need `flutter pub get` to regenerate them; Android is unaffected.
9. **Old CI runs stuck in "queued"** from 11 November on this branch are
   on GitHub's side and superseded by later runs; you can cancel them.

## 6. One-pass phone test checklist

Install the CI artifact or a local release build on one Android phone.
Start in **English, light**, then switch where noted.

**First launch and account**
1. Fresh install → splash (≈1.4 s) → 3 intro pages; Skip works; it never
   shows again (also not after Log out).
2. Sign up: try Next with empty fields (errors under fields); a 5-char
   password; go Back and forward (values kept); pick the birth date and
   **Girl/Boy**; type `3,4` for weight; on Reminders read the text, tap
   "Turn on reminders" → Android permission prompt appears; Summary shows
   everything + disclaimer → Create account → Home.
3. Sign up again with the same email → you land on step 1 with "already
   registered" under the email.
4. Log out → Forgot password → email prefilled → "Check your inbox".
5. Log in with a wrong password → red banner, form stays.

**Home and schedule**
6. Home: next dose card with countdown; progress "x of 10 doses given";
   quick actions; measurements show what you entered.
7. Schedule tab: age headings stay pinned while scrolling; chips;
   filters (Completed / Skipped empty state); FAB "Add reminder".
8. Open a dose in the future → Mark as given → confirmation → record
   sheet → fill clinic + lot → Save; record appears; **Undo** → back to
   pending, record gone. Turn on airplane mode, mark another dose →
   "Saved on this phone…" banner.

**Features**
9. Home → Vaccination card → **Share** (share sheet opens with a PDF; open
   it: English + Arabic, your clinic/lot shown) and **Print** (print
   preview).
10. Home → Growth → Add measurement (weight 4600 is refused, 4,6 is
    accepted) → chart with five curves and your dot; reading "Around the
    …th percentile" and the "not a diagnosis" line; switch Height/Head;
    edit and delete a measurement; Home weight tile updates.
11. Reminders → add "Vitamin D drops", every day, a time 2 minutes from
    now → **notification arrives**; add a one-off 2 minutes ahead →
    arrives; switch one off → it does not arrive; delete one.
12. **Restart the phone**, then wait for a daily reminder → it still
    arrives.

**Language, theme, size**
13. Settings → العربية: everything mirrors (chevrons, chart axis, step
    progress); Theme Dark and System.
14. The four Arabic checks from fix 11:
    - pending doses read **"قيد الانتظار"** (schedule chips, card PDF);
    - countdowns use the right plural forms: **"متبقٍ يومان"**,
      **"متبقٍ 3 أيام"**, **"متبقٍ 11 شهرًا"**; age headings **"شهران"**,
      **"4 أشهر"**, **"5 سنوات"**;
    - every number and date uses **Western digits 0–9** (dates, times,
      chart, PDF);
    - long vaccine names wrap to **two lines** with "…" in the dose title
      bar and the schedule rows.
15. Android Settings → Display → largest font (≈1.3): nothing cut off on
    Home, Schedule, Sign-up, Growth, Reminders.
16. TalkBack on: navigation tabs, status chips ("Status: Overdue"), the
    progress ring ("3 of 10 doses done") and switches are read.
17. Long-press the launcher icon area / themed icons on (Android 13+): the
    monochrome icon shows.

## 7. What could not be verified in the cloud

- **Real notifications**: delivery, the exact time, repeating ones, and
  survival across a reboot. The scheduling logic and keys are unit-tested;
  the OS behaviour is not.
- **The PDF share and print sheets** on a device. The PDF itself was
  generated and rendered here (Arabic shaping and layout checked by eye);
  the hand-off to Android was only tested with fakes.
- **Real-device layout**: tested on a 360×640 viewport at 1.0 and 1.3 in
  widget tests with the test font, not on hardware with Cairo at every
  size. Launcher icon masks were checked as images, not on a launcher.
- **Firestore against production**: the rules were tested only on the
  local emulator; offline behaviour was tested through the existing
  `WriteOutcome` logic, not with a real connection drop.
- **The signed release build**: built here debug-signed (as CI does for
  pull requests); signing was not touched.

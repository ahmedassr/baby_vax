# Baby Vax v1.1 — redesign plan

Written before any UI change, from a read of every screen on `main` at
`81c85c1` (the merge of PR #2).

Scope: (A) a full UI/UX redesign on a real design system with refreshed
branding, (B) three new features — vaccination record + shareable PDF card,
growth tracker, custom reminders.

Constraints that shape everything below:

- GetX + MVVM and the current folder layout stay. No new state management.
- Firebase stays on Spark: no Cloud Functions, no FCM, no server. Reminders
  stay local (`flutter_local_notifications`).
- Firestore rules stay strict (owner-only, `hasOnly`, default deny). Every new
  field and collection is optional and backward-compatible: a user document
  written by v1.0 must still validate and still load.
- Arabic RTL and English, dark mode, font scale to 1.3, 360×640 screens,
  TalkBack labels, 48dp targets — all must keep working.
- No medical content from memory. Growth reference data comes only from files
  downloaded from WHO in the session that added them, recorded in
  `docs/THIRD_PARTY.md`.

## 1. Audit — what is wrong now, screen by screen

### Cross-cutting problems

These are the reason a design system is the first commit, not the last.

1. **No theme to speak of.** `AppTheme` sets `fontFamily`,
   `scaffoldBackgroundColor`, a seeded `ColorScheme` and one elevated-button
   style. Everything else is decided inside widgets.
2. **`isDark ? X : Y` everywhere.** 20+ widgets branch on
   `context.isDarkMode` and hard-code a colour on each side
   (`ProfileCard`, `MeasurementCard`, `NextVaccinationCard`,
   `MedicalDateCard`, `TipCard`, `AppListItem`, `AppTextField`,
   `AppBottomNavigationBar`, `AppShimmerLoading`, `SplashView`, …). The
   `ColorScheme` that already exists is mostly ignored, so dark mode is a
   second hand-maintained palette that drifts.
3. **Contrast failures.** `AppColors.primary` (`#42A332`) is used as *text*
   on white and on `#F8F9FA` at **3.22:1** and **3.06:1** — below the 4.5:1
   AA minimum for body text. It is the colour of the "Next Vaccination"
   heading, the login/sign-up titles, the pending chip and every section
   header. `AppColors.textHint` `#999999` on white is 2.85:1. White on
   `AppColors.buttonLight` is not used, but `AppButton` paints
   `primary`-coloured text on `#E9F3E8`, 2.9:1.
4. **Font sizes are literals in screens.** `fontSize: 32`, `18`, `13`, `11`,
   `22` appear inline in `login_view`, `sign_up_view`, `tip_details_view`,
   `medical_date_status_badge`, `vaccination_count_badge`,
   `custom_app_bar`, `splash_view`. The type scale in `AppTextStyles` exists
   but is bypassed with `copyWith(fontSize: …)` on nearly every use.
5. **`AppTextStyles` is not a scale.** 25 entries across five overlapping
   families (`headLine*`, `title*`, `body*`, `text*`, `caption*`, `bold*`)
   with sizes 12–34 and no relation to Material's roles, so
   `Theme.of(context).textTheme` and the app's own styles disagree.
6. **No spacing scale.** `AppSpacing` has three `EdgeInsets` and nothing
   else; padding is written inline as 5, 6, 8, 10, 12, 14, 15, 16, 18, 20,
   22, 24, 28, 30, 32, 40, 64, 70. Vertical rhythm is produced by
   `5.sbh`/`20.sbh` calls scattered through build methods.
7. **Radii are ad hoc:** 8, 10, 12, 14, 15, 16, 18, 20, 24, 999 — and
   `MedicalDateCard` uses a three-corner radius that reads as a rendering
   bug.
8. **Shadows are hand-rolled per widget**, always `if (!isDark)`, with six
   different blur/offset/alpha combinations.
9. **`ScreenUtil` is half-applied.** `designSize: Size(414, 896)` with `.w`,
   `.h`, `.r` used in `BackIcon`, `CustomAppBar`, `base_extension`, and
   nowhere else. On a 360×640 phone that silently shrinks only those few
   widgets, so touch targets and gaps scale inconsistently. `BackIcon` is a
   `20.r` `CircleAvatar` inside a `24.w` box — about **24dp**, half the 48dp
   minimum.
10. **Loading/empty/error states are inconsistent.** Three different loading
    widgets (`AppShimmerLoading`, `CupertinoActivityIndicator`, bare
    `CircularProgressIndicator`); `onError` on four screens renders a
    `SizedBox.shrink()` and fires an alert dialog from a post-frame
    callback; empty states reuse the *Tips* string
    (`TipsView_empty_state_text`) on Home and on the schedule.
11. **Hard-coded English leaks.** `AppEmptyState` default message is
    `"No data found."`; `AlertWidget` button fallbacks are `'OK'` and
    `'Cancel'`; `SplashView` prints a literal `Baby Vax` (acceptable, it is
    the brand) in a literal `TextStyle` with a literal `Color(0xFF42A332)`.
12. **Accessibility gaps.** No `Semantics` on the status chip, the countdown
    badge or the measurement tiles; icon-only `IconButton`s in the app bar
    (edit, search, add) have no `tooltip`, so TalkBack announces only
    "button"; the bottom navigation bar hides both selected and unselected
    labels (`showSelectedLabels: false`), leaving four unlabelled icons.
13. **Dead UI.** The schedule's `FloatingActionButton.extended` has a
    `// TODO: Wire up add-medical-date flow` body — a button that does
    nothing. `MainMenuController.onSearchPressed` and `onAddPressed` are
    empty; `SearchOnMedicalDates`/`SearchOnTips` exist but are unreachable
    (no route). `MeasurementCard.onTap` is passed four empty closures.
    `UserCard` and `DetailCard` are unused. `AppTextField` and
    `LabeledTextField` both carry a `// TODO: implement build` comment above
    a finished build method.
14. **No forgot-password screen at all**, although the task list names one.

### Splash — `modules/splash`

- 4-second fixed delay before routing. That is a long time to look at a
  static logo, and it is wall-clock, not "until ready".
- Background is `AppColors.cardDark` (`0x454F4F4F`, a *translucent* grey) in
  dark mode, so the scaffold shows through — the splash looks washed out.
- Literal `TextStyle(fontSize: 24, color: Color(0xFF42A332))`, outside both
  the theme and the type scale.
- `const AppText(text: 'Baby Vax', style: TextStyle(...))` with a `Colors.grey`
  tagline at 14sp: 2.85:1 on the light background.

**Change:** cut the delay to ~1.6s (the animation length) and route as soon
as the animation finishes; theme-driven colours; brand wordmark from the
type scale; `Semantics(label: 'Baby Vax')`. Add the first-launch onboarding
hand-off here.

### Onboarding — new

Does not exist. v1.0 drops a first-time user straight onto Login with no
explanation of what the app does or why it wants notifications.

**Change:** three skippable intro pages (what the schedule is, reminders, the
record/growth card), shown once, flag in `GetStorage`
(`StorageKey.hasSeenOnboardingKey`). Page indicator, Skip in the top corner,
Next/Get started as the primary action. Routed from Splash before Login.

### Login — `modules/auth/login`

- Title at `fontSize: 32` in `AppColors.primary` → 3.22:1.
- "Create New Account" is a bare `InkWell` with 6dp padding — about 30dp
  tall, under the 48dp minimum, and bottom-right aligned where it reads as a
  footnote rather than the second action.
- No forgot-password link.
- No password visibility toggle.
- Errors arrive as a modal `AlertWidget` from a post-frame callback inside
  `onError`, which returns `SizedBox.shrink()` — so on a failed login the
  whole form disappears behind a dialog and comes back when it is dismissed.
- `AppButton` is the primary action but paints `primary` text on a very pale
  green fill at 2.9:1, and its own `headLineSmall.copyWith(fontSize: 22)`.
- Button is in `bottomNavigationBar`, so it sits above the keyboard but is
  visually detached from the form.

**Change:** design-system `AppPrimaryButton` with a filled brand background
and white label; inline field errors only (no dialog for validation);
`AppBanner` for auth failures; visibility toggle; forgot-password as a
48dp-high text button under the password field; "Create account" promoted to
a full-width secondary button.

### Forgot password — new

**Change:** new screen + route. Email field, one primary action, a success
state that says "check your inbox" without revealing whether the address is
registered, and the same offline/error handling as login.

### Sign-up — `modules/auth/sign_up`

- One long form: email, password, full name, date of birth, then four
  measurement fields, then the disclaimer, with a single "Sign Up" button at
  the bottom. On a 360×640 screen that is roughly three and a half screens of
  scrolling before anything can be submitted.
- **All eight fields are required**, including blood percentage and head
  size. A parent who does not know the haemoglobin figure cannot create an
  account.
- No `sex` field, so WHO growth percentiles are impossible for existing
  users (they are sex-specific).
- Validation runs only on submit, and then sets eight error strings at once.
- `Obx(() => LabeledTextField(controller: … ?? TextEditingController()))`:
  a fresh `TextEditingController` is created on every rebuild when the map
  lookup misses, and each `Obx` rebuilds the whole field.
- The four measurement fields are `SizedBox(width: 130)` inside a `Wrap`;
  at text scale 1.3 the labels ("Blood % (g/dl)") wrap to three lines and the
  fields stop lining up.
- Account creation and profile creation are two steps with a rollback
  (`authResult.user?.delete()`), but the user sees only one generic failure
  message.
- Success is an `AlertModel.success` dialog whose only button routes on —
  an extra tap for no information.

**Change:** a five-step stepper, which is the single biggest UX change in
this release:

1. **Account** — email, password (with strength hint and visibility toggle).
2. **Baby** — name, birth date, **sex** (new, needed for growth charts).
3. **Measurements** — weight, height, head circumference, haemoglobin, all
   optional, with a visible "Skip for now".
4. **Reminders** — explains what reminders do and when they arrive, then asks
   for the OS permission. Declining is fine and says so.
5. **Summary** — read-back of every value, the disclaimer, and "Create
   account".

Per-step validation; values survive Back; a progress indicator; and failures
land on the step that owns them (`email-already-in-use` → step 1,
offline → step 5 with a retry).

### Home — `modules/home`

- Information order is wrong: a profile card (name + email) is the hero, then
  four measurement tiles, and the **next due dose is last**, below the fold on
  a small screen. The next dose is the reason the app exists.
- `UserMeasurementCard` shows a 2×2 grid of values with no dates and four
  no-op `onTap`s.
- `NextVaccinationCard` starts with `20.sbh` inside its own padding, has the
  countdown badge absolutely positioned at `right: 16, top: 8` (so in RTL it
  stays on the right, pinned over the card's own corner), and embeds a
  `MedicalDateCard` that carries `margin: symmetric(vertical: 30)` — 60dp of
  dead space inside a card.
- When there is no pending dose the card renders its title and nothing else:
  no "all caught up" state.
- `onEmpty` shows the Tips empty-state string.
- The whole screen is one `RefreshableListBuilder` with `itemCount: 1`
  building a `Column`, i.e. a `CustomScrollView` wrapping a single child.
- No overall progress: a parent cannot see "7 of 10 doses done".

**Change:** next-dose hero card at the top (dose name, date, countdown,
status, one primary action), then a calm overall progress ring/bar, then
quick actions (export card, add measurement, add reminder), then the
measurements summary with its latest date, then the profile row moved to the
bottom. Distinct empty states: no schedule, all done, offline.

### Schedule — `modules/medical_dates`

- A flat chronological list of 10 cards with no grouping. "2 months",
  "4 months", "5 years" and "15 years" all look alike.
- The date is the card's headline and the vaccine name is the subtitle,
  which is backwards: parents look for the vaccine.
- `margin: EdgeInsets.symmetric(vertical: 30)` on every card, so the list is
  mostly whitespace and only two cards fit on a 640dp screen.
- Three-corner border radius (no top-right) with the count badge positioned
  into the gap — in RTL the badge lands on the wrong corner.
- Status chip and countdown badge say overlapping things, and "Pending" is
  shown in `AppColors.primary` at 3:1.
- A FAB that does nothing.
- No progress summary, no filter (completed/pending/overdue), no sticky age
  headers.

**Change:** doses grouped under age section headers (At birth, 2 months,
4 months, …) with a sticky header; the vaccine name as the headline and the
date beneath; one status chip per row (completed / pending / overdue /
skipped) with the countdown folded into the pending/overdue chip; a progress
summary card at the top; filter chips; the FAB wired to the new custom
reminder flow (feature B3) instead of being removed. All current behaviour
kept: date sort order, confirmation before marking a future dose,
Undo, reminder cancel/restore, the offline "Saved on this phone" message.

### Dose details — `modules/medical_date_details`

- Loading is a `CupertinoActivityIndicator` on Android.
- `onError` renders nothing and fires a dialog from a post-frame callback,
  then calls `setSuccess()` — so an error flashes the screen empty.
- Actions are a filled `AppButton` ("Mark as given") and a bare `TextButton`
  in error-red ("Mark as skipped") with no 48dp box, plus an "Undo" that uses
  the same filled style as the primary action.
- Nothing records *when* the dose was actually given, where, or which batch —
  which is what a clinic card needs (feature B1).
- No disclaimer on a screen that shows vaccine information.

**Change:** theme-driven card, status chip in the app bar area, a proper
destructive/secondary button pair, inline error banner instead of a dialog,
the disclaimer, and the new "record details" sheet from feature B1 plus the
"Export card" entry point.

### Tips / tip details — `modules/tips`, `modules/tip_details`

- `TipCard` hard-codes `cardDark`/`backgroundLight` and its own shadow.
- `TipDetailsView` sets `fontSize: 22`, `16`, `height: 1.6`,
  `letterSpacing: 0.07` inline and paints the title in `AppColors.primary`
  (3:1).
- `Image.network` with no fixed aspect ratio, so the card jumps when an image
  loads; the error state is a 80dp box with a faint icon.
- `DetailCard` is dead code.
- Empty state is the same Lottie + string as everywhere else.

**Change:** both onto the design system, `AspectRatio` + fade-in for images,
a real "no tips yet" empty state, and `SelectableText` for the body so a
parent can copy a sentence.

### Profile / edit — `modules/edit_user`

- Six unlabelled-by-type text fields in a column, 20dp apart, then a button
  70dp below.
- The **email field is editable but never applied** to Firebase Auth — only
  written into the Firestore document, so the profile silently disagrees with
  the sign-in email.
- No validation at all: empty name, letters in weight, anything.
- No sex or birth date, so the two fields the growth chart needs cannot be
  corrected.
- `initializeUserArgument` puts `"-"` in the name field when the name is
  null, and that `-` is then saved.
- `InternalScreenArgs.fromArgs` reads a single global slot in
  `ArgumentService`, which `late dynamic _argument` leaves uninitialised —
  opening the screen by route without setting the argument first throws.

**Change:** sectioned form (Baby / Measurements / Account), the email field
read-only with an explanation, numeric keyboards and unit suffixes,
validation per field, sex and birth date editable, and the latest-measurement
link to feature B2.

### Settings — `modules/setting`

- Five `AppListTitleItem` rows 20dp apart with no grouping or section
  headers; "Terms and Conditions" and "About us" have empty `onTap`s.
- The dark-mode row is a `SwitchListTile` whose label changes with its own
  state ("Dark Mode" / "Light Mode"), and there is no "follow system"
  option even though the app supports `ThemeMode.system` — opening Settings
  calls `loadThemePreference`, which writes nothing but displays the system
  value, so the switch looks like a user choice that was never made.
- `LanguageSelector` reads `controller.currentLanguage.value` outside an
  `Obx`, so the trailing "EN"/"AR" does not update until the screen rebuilds;
  both list rows call the same `changeLanguage()` toggle, so tapping
  "English" while already on English switches to Arabic.
- Logout clears the whole `GetStorage` box, including the onboarding flag.
- No app version, no licences page, no link to the privacy policy that exists
  in `docs/privacy-policy.html`.

**Change:** grouped sections (Appearance, Language, Reminders, About,
Account) with `AppSectionHeader`; theme as a three-way segmented control
(System / Light / Dark); language as a real radio group; a Reminders row
showing whether notifications are on; About with version, privacy policy,
licences; destructive actions last, visually separated. Logout keeps the
onboarding and language keys.

## 2. The design system

`lib/app/core/widget/`, and every screen is moved onto it. After the move,
`grep -nE "Color\(0x|fontSize: [0-9]"` over `lib/app/modules/` is empty.

### 2.2 Type

One scale, mapped onto Material's `TextTheme` roles so
`Theme.of(context).textTheme` and the app agree. Cairo, bundled, regular
weight only (`assets/google_fonts/Cairo-Regular.ttf` — synthetic weights
for w600/w700, as today).

| Role | Size | Weight | Height | Use |
| --- | --- | --- | --- | --- |
| `displaySmall` | 32 | w800 | 1.25 | Onboarding and splash wordmark |
| `headlineMedium` | 26 | w800 | 1.25 | Screen hero titles |
| `headlineSmall` | 22 | w700 | 1.3 | Section titles, app bar |
| `titleLarge` | 19 | w700 | 1.35 | Card titles, dose name |
| `titleMedium` | 17 | w700 | 1.4 | List row titles |
| `titleSmall` | 15 | w700 | 1.4 | Overlines, field labels |
| `bodyLarge` | 16 | w400 | 1.5 | Reading text |
| `bodyMedium` | 15 | w400 | 1.5 | Default body |
| `bodySmall` | 13 | w400 | 1.45 | Captions, helper text |
| `labelLarge` | 15 | w600 | 1.2 | Button labels |
| `labelMedium` | 13 | w600 | 1.2 | Chips |
| `labelSmall` | 11 | w600 | 1.2 | Badges |

Cairo's intrinsic line height is close to 2.0, which is why the existing
`AppTextStyles.base` pins `height: 1.3`. Every role above sets `height`
explicitly for the same reason.

`AppTextStyles` is kept as a thin deprecated shim mapping the old names onto
the new roles, so the move can be one screen per commit without a flag day.

### 2.3 Spacing

`AppSpacing` becomes a scale of `double` constants on a 4dp grid, plus the
`EdgeInsets` the old API exposed:

```
xxs 2   xs 4   sm 8   md 12   lg 16   xl 20   xxl 24   xxxl 32   huge 40
```

Screen gutter is `lg` (16). Card padding `lg`. Gap between cards `md` (12).
Gap between sections `xxl` (24). `.sbh`/`.sbw` stay but are only called with
scale values.

`ScreenUtil` stays registered (it is in `main.dart` and several widgets use
`.w`/`.h`), but **no new code uses it**: sizes are logical pixels so text
scaling and small screens behave predictably. The two existing 48dp-target
offenders (`BackIcon`, `CustomAppBar.leadingWidth`) are converted to fixed
dp.

### 2.4 Radius and elevation

```
radiusSm   8    chips, small controls
radiusMd  12    text fields, buttons
radiusLg  16    cards
radiusXl  24    sheets, hero card
radiusPill 999  status chips, badges
```

Three elevation levels only, defined once as `List<BoxShadow>` in a
`ThemeExtension` (`AppElevation`) so dark mode can use a border instead of a
shadow (shadows are invisible on dark surfaces, which is why every widget
currently writes `if (!isDark)`):

- `level0` — flat, no shadow, no border.
- `level1` — light: `0 1 3 rgba(0,0,0,.06)` + `0 1 2 rgba(0,0,0,.04)`;
  dark: 1px `outlineVariant` border.
- `level2` — light: `0 4 12 rgba(0,0,0,.08)`; dark: 1px border +
  `surfaceContainerHigh` fill.

## 4. New features

### B1 — Vaccination record + shareable PDF card

- Marking a dose **Completed** opens a sheet: date given (defaults to today),
  clinic/place, batch/lot, short note. All optional; "Save" with everything
  blank behaves exactly like today's one-tap complete.
- New **optional** fields on `users/{uid}/medical_dates/{id}`:
  `givenDate` (timestamp), `clinic`, `lot`, `note` (short strings). Rules add
  them to `hasOnly` and validate type/length; existing documents without them
  still pass, because `hasAll` stays `['name', 'date', 'state']`.
- "Export vaccination card" builds a bilingual (Arabic + English) A4 PDF on
  the device — baby details, then every dose with status, scheduled date,
  date given, clinic and lot — and hands it to the system share/print sheet.
  No network.
- Package: `pdf` + `printing` (both BSD-3, actively maintained, null-safe).
  Arabic needs the bundled Cairo TTF loaded as a `pdf` font and
  right-to-left paragraph direction.

### B2 — Growth tracker

- New collection `users/{uid}/measurements/{id}`: `date` (timestamp),
  `weightKg`, `heightCm`, `headCm` (numbers, all optional but at least one
  required), `note`. Owner-only, `hasOnly`, range-checked.
- History list + chart per metric, plotted against the **WHO Child Growth
  Standards** percentile curves for the baby's sex, 0–60 months, with a
  plain-language reading ("around the 50th percentile for weight") and an
  explicit "this is not a diagnosis" line plus the standing disclaimer.
- Reference data: the WHO z-score tables (L, M, S per month) downloaded in
  this session for weight-for-age, length/height-for-age and
  head-circumference-for-age, boys and girls. Source URLs, retrieval date and
  licence recorded in `docs/THIRD_PARTY.md` and in the generated Dart file's
  header. Percentile from the LMS formula; z→percentile by an
  Abramowitz–Stegun normal CDF approximation.
- Charts drawn with `CustomPainter` — no chart package, so no size cost and
  full control over RTL axes.
- The newest measurement also updates the profile's `weight`/`height`/
  `headSize` strings, so the existing Home tiles and Edit form keep working
  unchanged.
- Needs the baby's **sex**, which v1.0 never collected: sign-up step 2 adds
  it, Edit Profile can set it, and until it is set the chart shows history
  only with a one-tap "tell us the sex to see percentiles" prompt.

### B3 — Custom reminders and appointments

- New collection `users/{uid}/reminders/{id}`: `title`, `note`, `dateTime`
  (timestamp), `repeat` (`none` | `daily` | `weekly` | `monthly`),
  `enabled` (bool). Owner-only, `hasOnly`, validated.
- Scheduled through the existing `NotificationCoordinator` /
  `LocalNotificationService` with stable ids derived from the document id
  (`custom-<id>-main`, reusing `stableNotificationId`), so they survive
  reboot via the same app-start top-up, and are cancelled on delete or when
  disabled.
- The schedule screen's dead FAB becomes "Add reminder".

### Not now — multiple children

Deliberately out of scope for v1.1, because it is a data migration, not a
feature. Sketch for later:

1. One Auth user currently *is* one child: the child's name, birthday and
   measurements live on `users/{uid}`, and the schedule hangs off it at
   `users/{uid}/medical_dates`.
2. Target shape: `users/{uid}` keeps only account data (`email`, `uid`,
   settings, `activeChildId`), and each child becomes
   `users/{uid}/children/{childId}` with `medical_dates`, `measurements` and
   `reminders` as its subcollections.
3. Migration must be client-side (no Cloud Functions on Spark) and
   idempotent: on first launch of the version that introduces it, if
   `users/{uid}.schemaVersion` is absent, create
   `children/{generatedId}` from the current user fields, copy
   `medical_dates` into it in batches of ≤500, set `activeChildId` and
   `schemaVersion: 2`, and only then stop reading the old paths. Keep the old
   documents for one release so a rollback is possible.
4. Rules would need both shapes allowed during that window, with the old
   `medical_dates` path becoming read-only once `schemaVersion == 2`.
5. Reminder ids must then include the child id, or two children's doses on
   the same day collide; `stableNotificationId('<childId>-<doseId>-main')`.
6. UI: a child switcher in the app bar, per-child progress, and an "add
   child" flow that reuses sign-up steps 2–3.

That is a release of its own. The v1.1 schema changes above are all additive
so they do not make it harder.

# Baby Vax v1.1 — visual polish

Branch `feature/v1.1-polish` (draft PR ahmedassr/baby_vax#4, into
`feature/v1.1-redesign`). Written before the code changes it describes;
the contrast table at the end is generated from the theme by a test, so it
is always the shipped values.

Scope: colour, spacing, type, motion and the splash. **No behaviour, data,
Firestore rules or medical content changes, and no new features.** The same
hard rules as `v1.1-plan.md` apply.

## 1. Colour

### 1.1 What was wrong

From the "before" screenshots (360×760, light/dark, English/Arabic):

- **Dark mode is blue-grey, not green.** Surfaces were `#121417`…`#2D3233`
  (hue ≈ 200°), so the brand green floated on a cold slate background.
- **Dark cards are separated by bright borders.** The card colour was the
  same as (or darker than) the page, so every card needed a 1px outline,
  and the hero card a full-contrast `outline` ring. Busy and noisy.
- **Dark primary glares.** `#8ED97C` is a saturated green at tone ≈ 81; on a
  full-width button it is the brightest thing on screen.
- **The selected segment is brown.** Segmented buttons (Health 3/7/30 days,
  Growth Measurements/Milestones) use `secondaryContainer`, which was amber
  (`#FCEBC8` / `#3D2C06`): a third colour family next to the green with no
  meaning.
- **Light cards lean on shadows.** The page (`#F7F9F7`) is almost white, so
  separation came from drop shadows; the hero card's level-2 shadow reads
  as a grey smear under it.
- Status and chart colours were picked one by one, not from the same
  system as the green.

### 1.2 The palette

space, `material_color_utilities`), all built around the brand green's hue.
The brand green itself (`#42A332`, HCT hue 141.9, chroma 67, tone 60) is
unchanged and still used for the logo, the splash and the launcher icon.

### 1.3 Roles

How the app reads the scheme (unchanged contract, new values):

- `surfaceContainerLow` is **the page** (scaffold, app bar) in both modes.
- `surface` is **a card or sheet**: white in light; lifted, green-tinted
  dark in dark mode.
- `surfaceContainer` / `High` / `Highest` are fills *on* a card (text
  fields, tracks, chips), one step apart each.

Secondary is now a muted sage instead of amber. Amber keeps its meaning
(skipped, caution) through the status tokens below, not through
`secondary`, so a selected segment is no longer brown.

### 1.4 Depth: surface levels, not shadows

- **Light:** white cards on the tinted page give the separation. Resting
  cards keep a 1dp shadow at 4% (barely there); raised cards (the Home hero,
  dose summary) a soft 12dp shadow at 6%. No heavy shadows.
- **Dark:** shadows don't show, and borders were noisy. Cards are now
  lighter than the page (N12 on N6), which is enough on its own. Resting
  cards have **no border**; raised cards are one more step up
  (`surfaceContainer`, N17) instead of an outline ring.

### 1.7 Where colours live

Only in `lib/app/config/themes/`: `app_palette.dart` (tones), 
`app_color_schemes.dart` (roles), `app_status_colors.dart`,
`app_chart_colors.dart`, `app_elevation.dart`. `test/assets/design_system_test.dart`
still fails on any colour literal, Material palette colour or light/dark
branch in a screen.

The native splash and adaptive icon colours in `pubspec.yaml` are the page
colours above (`#F0F5ED` light, `#101510` dark), so the native splash hands
over to Flutter without a flash.

`test/theme/contrast_test.dart`, which fails if any text pair drops under
4.5:1 or any non-text pair under 3:1. The table in §4 is that test's
output.
